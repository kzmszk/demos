# VENEZIA

A browser 3D reconstruction of the whole main island of Venice, to **walk** (calli, campi, bridges, porticoes, with collisions), **ride in a gondola** (three canal routes, a rowing gondolier, or row yourself) or **fly** over. three.js WebGPU, Japanese and English (`#ja` / `#en`).

The city is generated from OpenStreetMap footprints, with hand-modelled landmarks: Piazza San Marco with St Mark's Basilica (west front with photo-mapped lunette mosaics; interior with five domes, three of them photo-mapped, the opus sectile floor and the iconostasis), the Campanile and Loggetta, Procuratie Vecchie and Nuove, the Ala Napoleonica, the Torre dell'Orologio, the Libreria and the two columns, the Doge's Palace, the Porta della Carta, the Ponte della Paglia and the Bridge of Sighs, the Rialto Bridge and the other Grand Canal crossings (the timber Accademia, the stone Scalzi, Calatrava's Costituzione), Caffè Florian (terrace with orchestra stage and its decorated rooms), La Fenice and the 1950s front of Santa Lucia station (the glass hall with its lettering, lit at night, the wings and the steps down to the Grand Canal). Every vaporetto stop floats as an ACTV pontoon with a glazed cabin and a gangway you can walk onto. A map in the corner shows where you are; a click (or M) opens the whole island. Light is baked per vertex with Blender Cycles; the sun is live. Sound is synthesised in the browser: seven solo-piano pieces that follow the scene (square, gondola, night, Florian, the Basilica, La Fenice, the title) and only natural sounds whose cause you can see (water on stone and hull, the oar, footsteps, pigeons, bells); it starts with the first click on the title.

State on 2026-10-05: deployed as `venice-2026-10-05`: the page opens on the Piazza and loads that first (a loading line on the title), shaders compile off the main thread and the city shader is a sixth of its size (Chrome's "Page Unresponsive" on a cold start), gzip tiles, the Basilica's narthex open (a blank wall stood 3 m inside the main portal); before that `venice-2026-10-04c` (the minimap, the vaporetto stops, bridge steps fitted to their banks, Santa Lucia, the phone profile). The last commit is `venice-2026-10-04b`. The release steps are at the end.

Only `public/` is published (`demo.json` has `"serve": "public"`). `tools/` is the build pipeline. The raw assets are **not in git**: they live in `/home/kazu/work/venice-assets/`.

## Run

```bash
python3 -m http.server 8417 --directory /home/kazu/work/demos     # the "demos" server in .claude/launch.json
# http://127.0.0.1:8417/venice/public/index.html
```

Needs a WebGPU browser (Chrome/Edge; on Linux Vulkan and `--enable-unsafe-webgpu`, as `tools/snap.mjs` passes them). Phones and tablets get a lighter page automatically (`?low=1` / `?low=0` force it): at most 1.1 MP drawn, MSAA instead of the post chain, two 1024 shadow cascades, the 1k skies (`sky_*_1k.hdr`), the 512 texture sets (`city_*_512.ktx2`, `art_512.ktx2`), shorter streaming radii and a smaller lightmap pool: about 0.65 GB of memory on a walk instead of 2.4 GB (an Android phone showed only a black screen). If the GPU still runs out of memory, the page says so instead of going black. The page opens on the title over its first view, walking in Piazza San Marco: the sky, the texture sets, the four tiles around the Piazza and the far view within 700 m download together (about 105 MB, a loading line on the title counts them), then the shaders and near detail of that view are made behind a veil, and the start button appears; the rest of the island streams in afterwards, nearest first. The whole island (`data/island`) is the default; `?set=name` loads another tile set (the test sets built by `run_set.sh`). Other query flags: `dbg=irr|nrm|alb|raw` (show baked light, normals, albedo), `async=0` (pipelines compiled the usual, blocking way), `post=0`, `refl=0`, `shadows=0`, `exp=`, `tm=agx|neutral`, `tex=1024|2048`. Keys: W A S D walk or fly, Shift run, drag to look, E/Q up/down and wheel for speed (fly), R to row yourself (gondola), M the island map (Esc closes it).

## Build

`python` below is the venv `/home/kazu/work/venice-assets/.venv/bin/python` (shapely, numpy, scipy, triangle, mapbox_earcut, Pillow, OpenCV; `credits.py` needs only `python3`); baking needs `blender` on the PATH (Cycles, OptiX GPU); `ktx` (KTX-Software) is in `venice-assets/tools`.

```bash
cd venice/tools && npm install                 # three, meshoptimizer, esbuild (once)

./run_island.sh gen      # OSM -> 200 m tiles (.npz, facade descriptors, walk rasters) in venice-assets/build/island
./run_island.sh bake     # Cycles per-vertex bake in 4x4-tile batches (SAMPLES=128), skips tiles that are up to date (~30 min)
./run_island.sh pack     # quantise + meshopt + gzip -> public/data/island, copy materials.json
./run_island.sh web      # esbuild -> public/app.js (dev build with source map)
./run_island.sh          # all four.  SET=name TILES="i,j;i,j" builds a test set (viewer: ?set=name); run_set.sh and run_slice.sh are the lighter variants
python build_tiles.py /home/kazu/work/venice-assets/build/island --walk-only --bbox -3400 -1600 2600 1800   # only the walk rasters (~25 s)
python map_build.py /home/kazu/work/venice-assets/build/island ../public/tex   # the minimap from the walk rasters (after any walk change)
python bridge_check.py                        # can a walker cross every bridge? (reads the walk rasters)

python art_build.py ../public/tex             # paintings, mosaics, dome photos -> art.ktx2 + art.json (items + commons/extra_items.json)
python art_build.py /home/kazu/work/venice-assets/build/art512 512          # the phones' set: copy art.ktx2 to public/tex/art_512.ktx2
python tex_build.py /home/kazu/work/venice-assets/build/tex1k --size 1024 --ktx   # texture arrays from gen/materials.py LAYERS; copy city_*_1024.ktx2 to public/tex
python tex_build.py /home/kazu/work/venice-assets/build/tex512 --size 512 --ktx   # the phones' set (city_*_512.ktx2)
python canals.py ../public/data/canals.json   # OSM canal graph + routes grand / sospiri / canalgrande
python interiors.py ../public/data/interiors.json
python sky_prep.py HDRI.hdr OUT_PREFIX AZIMUTH         # sun removed, sky rotated: sky/day = rustig_koppie_puresky at 235 deg, sky/night = qwantani_night_puresky at 120 deg
                                              # copy sky/day_2k.hdr and day.json to public/tex/sky_day.hdr / sky_day.json
python3 credits.py                            # public/credits.html (standard library only); rerun after art_build.py
node build_web.mjs                            # release bundle (minified); --dev adds the source map
```

Wikimedia Commons images are fetched with `commons_fetch.py OUTDIR "File:..."` (writes the licence record to `manifest.json`); `commons_search.py` and `commons_cat.py` find files.

## Architecture

1. **World** (`gen/world.py`, `osm.py`, `land.py`; land = `place=island` polygons minus water areas, where only multipolygon water relations count: a `type=waterway` relation is a centre line, and once swallowed half of Dorsoduro). OSM is projected to a local metric frame: origin at the Campanile, x east, y north, z up, water at z = 0, calli and fondamenta 1.10 m, the piazza 0.90 m. Land, water, buildings (height from tags or levels), streets, bridges. Buildings mapped in 3D (churches, campanili) are replaced by their `building:part`s (`parts.py`, `roofs.py`). `streets.py` reconciles calli with building outlines (OSM outlines often swallow the fondamenta): a pedestrian way running along an outline trims the building back; one passing right through it (or tagged `tunnel=building_passage` / `covered=yes`) becomes a sottoportego with a floor, walls, a beamed ceiling and the facade open below the first floor. `pontoons.py` takes the vaporetto stops out of the buildings (OSM draws them as `man_made=pier` polygons, `public_transport=platform` buildings or roofs standing in the water; they used to come out as plastered houses in the canal, or not at all) and makes each a floating pontoon: near-black hull 0.8 m above the water, plank deck, a glazed cabin under the mapped roof (open to the water, benches, lamps lit in the night bake, ACTV-yellow name boards) and one straight gangway to the quay where OSM puts it, never across another pontoon or against a wall; pontoons out of reach hang off a neighbour; paved jetties stay at quay level. Moored museum ships (`building=ship`) become boats.
2. **Generators**. `city.py` makes generic Venetian buildings (party-wall classification, facade descriptors with openings, bands and shutters, hipped roofs from the medial axis); `ground.py` the open ground, copings and canal walls; `bridges.py` the stepped brick footbridges; `props.py` prop templates (poles, lanterns, chimneys, boats; the viewer bakes each tile's props into one mesh). Bridges take their axis from each water crossing of the OSM line; each flight of steps is fitted to the open ground beyond its bank (steeper treads, then a shorter landing, then higher risers), so it stops short of a wall instead of running into it; crossings of 40 to 120 m of water (Ponte San Pietro, Quintavalle, the Lavraneri...) get a timber footbridge on piles; OSM's gangways to vaporetto stops (tagged as bridges, a fan of them at the Ferrovia) are left to the stops; a bridge is left out of the walk raster only when there is no walkable ground straight ahead of a foot nor beside it (a private bridge to a door). `gen/hero/*` model the landmarks bay by bay with `vk/`; the Basilica uses its own frame, turned 3.5° from the piazza axis (`common.rotated_frame`), because OSM's domes, outline and central arch all sit that way.
3. **Tiles**. `build_tiles.py` cuts the island into 200 m tiles (30 x 17 grid, 307 built). Each tile has a static mesh with per-vertex attributes, instanced props, 1 m facade bake grids, facade descriptors, and a 0.25 m walk raster (R = walkable height code, G = water).
4. **Bake**. `bake.py` (Blender Cycles) bakes irradiance per vertex and per facade grid: sky plus all indirect light. The sun's direct light is drawn live with cascaded shadow maps. `day` and `night` modes; at night the moon is a sun lamp, every lantern prop and every cluster of hand-modelled lamp glass is a point light, lit windows are emissive panes, and spotlights floodlight the Basilica front and the Campanile.
5. **Pack**. `pack.py` quantises (positions in a per-tile cube as uint16, snorm8 normals and tangents, RGBM8 irradiance, light denoising) and builds the far LOD: roofs and upper walls, ground, heroes, plus one quad strip per facade with procedural windows. `pack.mjs` meshopt-encodes the streams and simplifies the far LOD (20 MB for the whole island; with the full tiles, day and night light, 342 MB).
6. **Viewer** (three.js WebGPU, TSL). Start-up (`main.js`, `tiles.js` `prefetch`): the first view's files are fetched together with the textures and handed to `Tiles`, which loads nothing beyond that view (`tiles.cap`) until `tiles.pending()` and the pipelines in flight are both zero for 10 frames; then the veil lifts and the start button shows. Tile binaries are gzip files inflated with `DecompressionStream` (another 20 to 45% off the meshopt streams; the host does not compress `application/octet-stream`). Shaders: the main scene's render pipelines go through `createRenderPipelineAsync` (three.js does so whenever `Pipelines.getForRender` gets a promise list; `main.js` passes one) and an object is drawn from the first frame its pipeline is ready. Made synchronously they compile on the GPU process's main thread, and the renderer's thread blocks behind them as soon as its command buffer fills: with a cold shader cache that was 14 to 35 s at a time. Drawing done once (PMREM of the sky) and the post passes stay synchronous, since a skipped one-time draw never happens. `citymat.js` keeps its running values in variables evaluated in order at the top of the fragment shader (`V()`, `CityMaterial.setupDiffuseColor`): as plain expressions each `select()` re-generated everything before it in both branches, a 0.5 MB shader with 230 albedo samples that a driver took 15 to 25 s to compile (now 76 KB, under 1 s). Memory: every mesh is uploaded as soon as it is built and its CPU arrays are emptied (`tiles.js` `toGPU`; three.js's WebGPU backend never reads an array again unless its version changes; the emptied arrays keep their type, which gives the vertex formats), and so are the textures' (`freeOnUpload`); hero splits share their vertex buffers; tiles keep only the facade light and the prop instances, and props are built only within their radius. Before this a walk to the Rialto held 1.5 GB of typed arrays. Performance rules learnt the hard way: no `InstancedMesh` (three.js gives each one a uniquely named instance-matrix buffer in the shader, so every tile compiled new pipelines: multi-second stalls), shared uniforms in `renderGroup` (the default object group re-uploaded the material tables on every draw), detailed facade chunks built a few facades per frame, one coarse-facade mesh per tile, the drawing size capped near 3.7 MP. `window.__perf` logs slow phases and frames. Without WebGPU the page explains how to enable it (the WebGL2 fallback cannot carry the city). `tiles.js` keeps every tile's far LOD loaded and streams the rest by distance: full tile within 380 m, hand-modelled heroes in full detail within 260 m, a facade lightmap atlas within 150 m, 50 m chunks of detailed facades (openings, sills, shutters, balconies) within 75 m, props within 280 m. `citymat.js` is one texture-array PBR material with Venetian weathering and the baked light as indirect diffuse; `water.js` planar reflection; `controls.js` fly, walk (collisions against the walk raster, eye 1.62 m) and boat; `minimap.js` the corner map (the walk raster as an image: what is light can be walked on); `gondola.js` the boat, the gondolier (arm IK) and `GondolaRide` along the canal routes; `main.js` the renderer, sky, sun, post (GTAO, TRAA, bloom), interior eye adaptation and `window.VEN`.

## Verify headlessly

```bash
cd venice/tools
node snap.mjs out.jpg "set=island" shots.json     # [{ "name": "piazza", "eval": "VEN.place('piazza')", "wait": 1500, "settle": 1200 }]  ->  out-piazza.jpg
```

`startprobe.mjs out.json "query" [steps.json]` measures a cold start in a fresh profile (the NVIDIA shader cache off unless `WARM=1`): every pipeline and shader module made, main-thread long tasks, frame gaps, the loading line until the first view is ready (`WAITPREP=1`), page screenshots of the loading screen (`SHOTS=ms,ms`) and of the title (`TITLE_SHOT=1`), CPU profiles of steps (`"profile": true`), `BPS=` slows each file to that many bytes/s.

`snap.mjs` starts a static server and headless Chrome on the real GPU (`W`, `H` set the size, `PROBE=1` prints the WebGPU adapter), waits for `VEN.ready`, runs each `eval`, lets the tiles stream (`VEN.settle`) and saves `VEN.capture()`. Headless Chrome does not composite WebGPU canvases, so a normal screenshot of the page shows only the DOM overlay: use `VEN.capture()`. Hooks: `VEN.place(id)` (`piazza florian florian_in basilica piazzetta sospiri rialto accademia fenice fenice_in calle ferrovia`), `VEN.minimap.toggle()`, `VEN.route(name, s, speed)` (`grand sospiri canalgrande`), `VEN.walkAt(x, y, yaw)`, `VEN.look(px, py, pz, tx, ty, tz)`, `VEN.mode(m)`, `VEN.info()`, `VEN.tiles.breakdown(VEN.camera)`, `VEN.controls.pitch`.

## Film

`film.mjs` makes a short film of the viewer, cut on the bars of its own title music (bars 0-11, then 32-35 of the title piece, about 68 s):

```bash
node film.mjs scout OUTDIR [shot,shot]     # three stills per shot (960x540) to frame the shots
node film.mjs render OUTDIR                # every frame at 1920x1080 / 30 fps (JPEG), then the sound (amb.wav, music_full.wav, cut.json)
python film_mix.py OUTDIR                  # the music cut + the natural sounds, -16 LUFS, OUTDIR/venezia.mp4
```

The shots are in `film_shots.mjs` (walk: a path on the ground, eye height from the walk raster; fly: a path and a look-at path; boat: a gondola route; captions JA/EN, the title, the end card). `film_page.js` runs in the page: the app is stepped at a fixed 1/30 s (`VEN.step`, the animation loop stopped), every frame waits until its tiles, near detail and pipelines are complete, and the sound is rendered afterwards with an `OfflineAudioContext` from the scene state each frame saw (footsteps, water, the oar, the rooms) plus the title piece. `FILM.center(path)` puts a path down the middle of a calle. The 2026-10-05 film is in `venice-assets/film/` (`venezia.mp4`, `venezia_web.mp4`). Published at `/venice/film` (`public/film.html`, linked from the gallery card as 紹介動画 · Film): the video plays from the R2 bucket through the gallery Worker's `/media/movies/venezia-film/video.mp4` (uploaded with `npx wrangler r2 object put demos-media/movies/venezia-film/video.mp4 --file ... --content-type video/mp4 --remote`), because static assets answer a byte range with the whole file and Safari plays no video without ranges; `public/movie/venezia.mp4` (a 2-pass 2.7 Mbps encode, under the 25 MiB file limit) is the fallback `<source>`. The video is not in git (`venice/.gitignore`): copy it from `venice-assets/film/` into `public/movie/` before a deploy.

## Gallery and release

`demo.json` has 8 cover shots driven through `VEN` and `"gpu": "webgpu"`, which makes `gallery/shoot.mjs` start Chrome with WebGPU on (Vulkan on Linux). Headless Chrome does not composite a WebGPU canvas into a page screenshot, so every shot ends with `VEN.settle()` (tiles streamed in) and `VEN.freeze()`, which lays the rendered frame over the canvas, under the UI. Before deploying: build without `--dev`, delete `public/app.js.map` and the test sets in `public/data` (`test`, `tiles`, `bf`, ...; keep `island`, `materials.json`, `canals.json`, `interiors.json`), re-run `python3 tools/credits.py`, and check that no file is over Cloudflare's 25 MiB limit. The first view needs about 105 MB (textures 61 MB, the four Piazza tiles 36 MB, the far view around it 5 MB); the whole island is about 330 MB of tiles.
