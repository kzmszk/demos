# VENEZIA

A browser 3D reconstruction of the whole main island of Venice, to **walk** (calli, campi, bridges, porticoes, with collisions), **ride in a gondola** (three canal routes, a rowing gondolier, or row yourself) or **fly** over. three.js WebGPU, Japanese and English (`#ja` / `#en`).

The city is generated from OpenStreetMap footprints, with hand-modelled landmarks: Piazza San Marco with St Mark's Basilica (west front with photo-mapped lunette mosaics; interior with five domes, three of them photo-mapped, the opus sectile floor and the iconostasis), the Campanile and Loggetta, Procuratie Vecchie and Nuove, the Ala Napoleonica, the Torre dell'Orologio, the Libreria and the two columns, the Doge's Palace, the Porta della Carta, the Ponte della Paglia and the Bridge of Sighs, the Rialto Bridge and the other Grand Canal crossings (the timber Accademia, the stone Scalzi, Calatrava's Costituzione), Caffè Florian (terrace with orchestra stage and its decorated rooms) and La Fenice. Light is baked per vertex with Blender Cycles; the sun is live. Sound is synthesised in the browser: seven solo-piano pieces that follow the scene (square, gondola, night, Florian, the Basilica, La Fenice, the title) and only natural sounds whose cause you can see (water on stone and hull, the oar, footsteps, pigeons, bells); it starts with the first click on the title.

State on 2026-10-04: complete and verified headlessly (day and night bakes for all 307 tiles, the landmarks, interiors, sound, credits, covers). Not committed or deployed; the release steps are at the end.

Only `public/` is published (`demo.json` has `"serve": "public"`). `tools/` is the build pipeline. The raw assets are **not in git**: they live in `/home/kazu/work/venice-assets/`.

## Run

```bash
python3 -m http.server 8417 --directory /home/kazu/work/demos     # the "demos" server in .claude/launch.json
# http://127.0.0.1:8417/venice/public/index.html
```

Needs a WebGPU browser (Chrome/Edge; on Linux Vulkan and `--enable-unsafe-webgpu`, as `tools/snap.mjs` passes them). The whole island (`data/island`) is the default; `?set=name` loads another tile set (the test sets built by `run_set.sh`). Other query flags: `dbg=irr|nrm|alb|raw` (show baked light, normals, albedo), `post=0`, `refl=0`, `shadows=0`, `exp=`, `tm=agx|neutral`, `tex=1024|2048`. Keys: W A S D walk or fly, Shift run, drag to look, E/Q up/down and wheel for speed (fly), R to row yourself (gondola).

## Build

`python` below is the venv `/home/kazu/work/venice-assets/.venv/bin/python` (shapely, numpy, scipy, triangle, mapbox_earcut, Pillow, OpenCV; `credits.py` needs only `python3`); baking needs `blender` on the PATH (Cycles, OptiX GPU); `ktx` (KTX-Software) is in `venice-assets/tools`.

```bash
cd venice/tools && npm install                 # three, meshoptimizer, esbuild (once)

./run_island.sh gen      # OSM -> 200 m tiles (.npz, facade descriptors, walk rasters) in venice-assets/build/island
./run_island.sh bake     # Cycles per-vertex bake in 4x4-tile batches (SAMPLES=128), skips tiles that are up to date (~30 min)
./run_island.sh pack     # quantise + meshopt -> public/data/island, copy materials.json
./run_island.sh web      # esbuild -> public/app.js (dev build with source map)
./run_island.sh          # all four.  SET=name TILES="i,j;i,j" builds a test set (viewer: ?set=name); run_set.sh and run_slice.sh are the lighter variants

python art_build.py ../public/tex             # paintings, mosaics, dome photos -> art.ktx2 + art.json (items + commons/extra_items.json)
python tex_build.py /home/kazu/work/venice-assets/build/tex1k --size 1024 --ktx   # texture arrays from gen/materials.py LAYERS; copy city_*_1024.ktx2 to public/tex
python canals.py ../public/data/canals.json   # OSM canal graph + routes grand / sospiri / canalgrande
python interiors.py ../public/data/interiors.json
python sky_prep.py HDRI.hdr OUT_PREFIX AZIMUTH         # sun removed, sky rotated: sky/day = rustig_koppie_puresky at 235 deg, sky/night = qwantani_night_puresky at 120 deg
                                              # copy sky/day_2k.hdr and day.json to public/tex/sky_day.hdr / sky_day.json
python3 credits.py                            # public/credits.html (standard library only); rerun after art_build.py
node build_web.mjs                            # release bundle (minified); --dev adds the source map
```

Wikimedia Commons images are fetched with `commons_fetch.py OUTDIR "File:..."` (writes the licence record to `manifest.json`); `commons_search.py` and `commons_cat.py` find files.

## Architecture

1. **World** (`gen/world.py`, `osm.py`, `land.py`; land = `place=island` polygons minus water areas, where only multipolygon water relations count: a `type=waterway` relation is a centre line, and once swallowed half of Dorsoduro). OSM is projected to a local metric frame: origin at the Campanile, x east, y north, z up, water at z = 0, calli and fondamenta 1.10 m, the piazza 0.90 m. Land, water, buildings (height from tags or levels), streets, bridges. Buildings mapped in 3D (churches, campanili) are replaced by their `building:part`s (`parts.py`, `roofs.py`). `streets.py` reconciles calli with building outlines (OSM outlines often swallow the fondamenta): a pedestrian way running along an outline trims the building back; one passing right through it (or tagged `tunnel=building_passage` / `covered=yes`) becomes a sottoportego with a floor, walls, a beamed ceiling and the facade open below the first floor.
2. **Generators**. `city.py` makes generic Venetian buildings (party-wall classification, facade descriptors with openings, bands and shutters, hipped roofs from the medial axis); `ground.py` the open ground, copings and canal walls; `bridges.py` the stepped brick footbridges; `props.py` prop templates (poles, lanterns, chimneys, boats; the viewer bakes each tile's props into one mesh). Bridges take their axis from each water crossing of the OSM line; the steps always start on the banks; crossings of 40 to 120 m of water (Ponte San Pietro, Quintavalle, the Lavraneri...) get a timber footbridge on piles; a bridge whose landing is a building with no calle (a private bridge to a door) or water is left out of the walk raster. `gen/hero/*` model the landmarks bay by bay with `vk/`; the Basilica uses its own frame, turned 3.5° from the piazza axis (`common.rotated_frame`), because OSM's domes, outline and central arch all sit that way.
3. **Tiles**. `build_tiles.py` cuts the island into 200 m tiles (30 x 17 grid, 307 built). Each tile has a static mesh with per-vertex attributes, instanced props, 1 m facade bake grids, facade descriptors, and a 0.25 m walk raster (R = walkable height code, G = water).
4. **Bake**. `bake.py` (Blender Cycles) bakes irradiance per vertex and per facade grid: sky plus all indirect light. The sun's direct light is drawn live with cascaded shadow maps. `day` and `night` modes; at night the moon is a sun lamp, every lantern prop and every cluster of hand-modelled lamp glass is a point light, lit windows are emissive panes, and spotlights floodlight the Basilica front and the Campanile.
5. **Pack**. `pack.py` quantises (positions in a per-tile cube as uint16, snorm8 normals and tangents, RGBM8 irradiance, light denoising) and builds the far LOD: roofs and upper walls, ground, heroes, plus one quad strip per facade with procedural windows. `pack.mjs` meshopt-encodes the streams and simplifies the far LOD (20 MB for the whole island; with the full tiles, day and night light, 342 MB).
6. **Viewer** (three.js WebGPU, TSL). Performance rules learnt the hard way: no `InstancedMesh` (three.js gives each one a uniquely named instance-matrix buffer in the shader, so every tile compiled new pipelines: multi-second stalls), shared uniforms in `renderGroup` (the default object group re-uploaded the material tables on every draw), detailed facade chunks built a few facades per frame, one coarse-facade mesh per tile, the drawing size capped near 3.7 MP. `window.__perf` logs slow phases and frames. Without WebGPU the page explains how to enable it (the WebGL2 fallback cannot carry the city). `tiles.js` keeps every tile's far LOD loaded and streams the rest by distance: full tile within 380 m, hand-modelled heroes in full detail within 260 m, a facade lightmap atlas within 150 m, 50 m chunks of detailed facades (openings, sills, shutters, balconies) within 75 m, props within 280 m. `citymat.js` is one texture-array PBR material with Venetian weathering and the baked light as indirect diffuse; `water.js` planar reflection; `controls.js` fly, walk (collisions against the walk raster, eye 1.62 m) and boat; `gondola.js` the boat, the gondolier (arm IK) and `GondolaRide` along the canal routes; `main.js` the renderer, sky, sun, post (GTAO, TRAA, bloom), interior eye adaptation and `window.VEN`.

## Verify headlessly

```bash
cd venice/tools
node snap.mjs out.jpg "set=island" shots.json     # [{ "name": "piazza", "eval": "VEN.place('piazza')", "wait": 1500, "settle": 1200 }]  ->  out-piazza.jpg
```

`snap.mjs` starts a static server and headless Chrome on the real GPU (`W`, `H` set the size, `PROBE=1` prints the WebGPU adapter), waits for `VEN.ready`, runs each `eval`, lets the tiles stream (`VEN.settle`) and saves `VEN.capture()`. Headless Chrome does not composite WebGPU canvases, so a normal screenshot of the page shows only the DOM overlay: use `VEN.capture()`. Hooks: `VEN.place(id)` (`piazza florian florian_in basilica piazzetta sospiri rialto fenice calle`), `VEN.route(name, s, speed)` (`grand sospiri canalgrande`), `VEN.walkAt(x, y, yaw)`, `VEN.look(px, py, pz, tx, ty, tz)`, `VEN.mode(m)`, `VEN.info()`, `VEN.tiles.breakdown(VEN.camera)`, `VEN.controls.pitch`.

## Gallery and release

`demo.json` has 8 cover shots driven through `VEN` and `"gpu": "webgpu"`, which makes `gallery/shoot.mjs` start Chrome with WebGPU on (Vulkan on Linux). Headless Chrome does not composite a WebGPU canvas into a page screenshot, so every shot ends with `VEN.settle()` (tiles streamed in) and `VEN.freeze()`, which lays the rendered frame over the canvas, under the UI. Before deploying: build without `--dev`, delete `public/app.js.map` and the test sets in `public/data` (`test`, `tiles`, `bf`, ...; keep `island`, `materials.json`, `canals.json`, `interiors.json`), re-run `python3 tools/credits.py`, and check that no file is over Cloudflare's 25 MiB limit. The first load is about 120 to 190 MB (textures 55 MB, far LOD 20 MB, the full tiles around the camera).
